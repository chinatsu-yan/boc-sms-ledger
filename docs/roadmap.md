# 开发路线

**状态：已完成仓库及需求文档初始化，并整理九条完整结构合成用例、七条边界输入。第二阶段的初始样本规范已完成；工程、解析代码和真机验证均尚未开始。**

## 阶段 1：Android 工程与历史短信读取

- [ ] 选择并记录 Android 技术栈、SDK 和依赖版本。
- [ ] 建立可构建的应用工程和本地持久化结构。
- [ ] 实现短信权限申请及拒绝、撤销权限后的正常提示。
- [ ] 提供历史时间范围选择，读取现存短信并筛选目标银行候选。
- [ ] 保存来源标识和原文，重复导入同一来源记录保持幂等。

验收：在实际测试设备读取选定范围的现存短信；权限不足时应用正常运行并说明所需操作；重启后记录保留。

## 阶段 2：短信模板解析

- [x] 根据首批九条完整短信建立七种模板的合成用例与字段预期。
- [ ] 在解析器和实际设备上验证这些模板，并记录覆盖范围。
- [ ] 实现中国银行借记卡收支事件解析。
- [ ] 实现 Visa 原币消费、撤销、成功退货及购汇还款解析。
- [ ] 正确处理日元千分位、RMB/CNY、缺少年份和双币种还款。
- [ ] 区分非交易短信与未识别交易候选。
- [ ] 保存解析器版本、状态、币种与精确金额。
- [ ] 为币种、金额精度、交易方向和关键格式差异编写有实际判别价值的测试。

验收：USD 0.53 与 SGD 1.38 等示例不会被识别为人民币；已验证模板结果正确；未知格式进入可查看的待确认状态。

## 阶段 3：关联与记账规则

- [ ] 保留消费与撤销原始事件并实现保守关联。
- [ ] 处理全额、部分撤销、同额多笔、撤销先到、原消费缺失。
- [ ] 实现手动关联、解除关联和分类修正。
- [ ] 区分本人账户间转账、信用卡还款与真实收入/消费。
- [ ] 关联购汇还款与借记卡扣款证据，防止重复计账。
- [ ] 区分退款与撤销，确定退款发生期与原消费归属期的报表口径。
- [ ] 形成按账户、按币种汇总的数据查询。
- [ ] 对重复扫描、超额撤销、还款重复计入消费等关键风险编写测试。

验收：确认同笔 SGD 1.38 消费与撤销后净额为零；存在多个候选时不随意关联；重复扫描不增加交易数；还款本金不重复计算消费。

## 阶段 4：新短信接入

- [ ] 新短信使用与历史读取一致的解析和保存流程。
- [ ] 处理多段短信。
- [ ] 解决广播事件与后续短信提供方记录之间的对应关系。
- [ ] 打开应用时增量补扫，恢复已存入手机但尚未处理的短信。
- [ ] 检查重启、权限变化和目标设备后台行为。

验收：新短信可形成记录，随后历史补扫不会产生第二笔；无法保证的设备行为和覆盖限制有明确记录。

## 阶段 5：最小可用界面与真机验证

- [ ] 交易列表与账户、币种、时间筛选。
- [ ] 各币种汇总与消费/撤销状态展示。
- [ ] 原始短信及解析结果查看。
- [ ] 未识别短信和待确认关联处理。
- [ ] 使用实际设备与脱敏模板核对结果。
- [ ] 记录安装方式、支持模板、已知限制和验证结果。

验收：从短信读取到查看、关联、修正及汇总形成可用闭环；能解释每条统计结果对应的原始证据。届时再发布首个可安装版本。

## 实施原则

优先完成真实短信到正确记账的闭环。尚未实现的功能保持未完成状态；不为初始化文档建立空壳测试或虚构构建通过记录。
