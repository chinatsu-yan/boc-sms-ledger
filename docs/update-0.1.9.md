# 0.1.9 — 汇率来源与旧缓存修复

基线0c54615（0.1.8），包名local.boc.ledger，版本0.1.9/code10；沿用debug签名，没有新增权限。账本数据库、原始短信、人工修正、分类与关联不改。

## 原因与修复

用户提供的两张图片已经实际查看，补充图片确认异常报价来自Frankfurter的BCC单一来源。旧代码按来源日期降序排序，ECB仅在同日优先；周末其它来源日期更新时，会覆盖上一个工作日的ECB参考价。该单一来源报价又缓存30天。原币解析、乘除方向与精确十进制计算没有发现错误；本次不重写这些链路。

现在优先采用近14天内、不晚于交易日的ECB报价；ECB未覆盖的币种采用Frankfurter综合参考报价，不再随意挑一个最新单一来源。仍按原币兑USD相乘，历史报价依交易日期缓存，最新USD/CNY使用独立LATEST缓存。假日流水在美元参考值旁标出实际参考日期，点击可看完整日期、汇率和来源。

汇率缓存单独升级至v2：失效旧非ECB单一来源报价及旧失败记录，已有ECB报价保留。仅影响独立fx-cache.db的rates表；不删除或重解析账本。联网成功后重新获取，暂时联网失败则显示缺价，不继续沿用已知不符合新规则的旧价。

## 数字例证（交易金额为合成）

- 异常来源率0.00032652使JPY10,000折为USD3.2652（显示3.27）。公开ECB在2026-10-02的每EUR参考价为USD1.1225、JPY176.99，交叉率1.1225÷176.99≈0.006342166224；同样JPY10,000为USD63.42166224（显示63.42）。周日使用此前周五的可用参考日，不能标成周日原始报价。
- 离线回归采用独立合成率0.00625：JPY10,000减已关联退款JPY2,000，净额×0.00625=USD50；再加USD20，外币合计USD70；最新合成USD/CNY7.2得人民币参考504。另有CNY300单列，不进入USD池。
- 中间不按展示小数位舍入；KWD三位金额、缺率与部分覆盖沿用现有针对性测试。

官方契约：[Frankfurter](https://frankfurter.dev/)说明默认综合价、指定provider单一来源及amount×rate的换算方向。[ECB公开数据](https://data-api.ecb.europa.eu/service/data/EXR/D.USD+JPY.EUR.SP00.A?startPeriod=2026-10-02&endPeriod=2026-10-02&format=csvdata)用于独立核对，不是App新增行情服务。

## 验证范围

核心BillingTest与CreditReferenceTest定向回归，Android构建与lint；API26模拟器针对行情来源选择、非ECB币种综合价、精确数字、缓存迁移/离线及参考日期界面做检查。全部交易样例为合成数据，用户截图不入Git。

本次Frankfurter公开端点实测返回HTTP522，不能声称已完成线上全链路验证；ECB公开核对请求成功。接口流程用模拟响应检验，用户手机需联网重新取价。未访问真实手机、未跑多设备矩阵，不推送或发布release。

## 使用

覆盖安装0.1.9，不卸载。再次打开信用卡流水或账期页面会自动读取新规则报价。若服务暂不可用，等恢复后使用“更多 → 刷新公开参考汇率”。不需要重新导入短信或重做人工分类。
