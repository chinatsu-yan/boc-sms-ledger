# 0.1.3：自动扫描、账户分区与信用卡参考估算

应用 0.1.3 / versionCode 4；包名 local.boc.ledger、minSdk 26 / targetSdk 35 和原调试签名保持。短信解析器仍为版本 3，原有七种模板、币种校验、原文、人工更正、来源键和确认关联保留。未推送、合并或发布 release，未访问真实手机。

## 默认只看已识别交易

- 主列表/原币汇总仅显示解析成功或已有人工确认、来源和币种已确认、未排除的交易。用途不确定但模板已识别的借记卡转入/转出仍显示，用途待确认，不自动当收入/消费。
- 信用卡和借记卡由明确的事件类型分区；没有有效事件的原文不猜账户类型。购汇还款属于信用卡事件，借记卡扣款侧金额仍在详情，不再额外当消费。
- 其它短信、未知模板/币种草稿、来源待确认、已排除记录不出现在默认列表，原始记录没有删除。可从「更多 → 保留的原始记录」查看/修正，或执行「重新解析（保留人工修正）」。

## 自动扫描：原有与补齐的部分

0.1.2 已有短信广播触发 JobScheduler 延迟补扫、启动补扫和同来源幂等，但依赖用户先手动完成历史导入，授权回调仍打开日期选择器；前台常驻时也未监听短信库变动。

0.1.3 改为：

1. 首次授予 READ_SMS 后自动导入现存中行候选短信，初始范围从 0 到当前接收时刻，不再要求点“开始扫描”。已有范围和水位不会重置，用户此前主动暂停也不会被启动流程擅自恢复。
2. 新短信广播继续仅唤醒任务，从系统 Inbox 读取；约 2 秒后读取，再有界延后约 10/30 秒复扫，处理广播先于系统入库的情况。
3. 前台通过系统 ContentObserver 观察短信库变化，合并约 2 秒后补扫并刷新列表；回到 App 自动增量补扫。没有周期定时轮询、新前台服务或额外后台权限。
4. 两条入口共用提供方来源键，广播正文不单独生成交易。补扫从原有水位前 24 小时开始，完整成功后才推进；中断/拒绝权限可安全重试。
5. 拒绝或撤销短信权限时，停止系统短信读取，已有本地账目仍可查看。工具菜单可暂停/恢复；可选历史范围补读保留，系统新恢复的更早历史可能需要此入口。

Android 后台/电池限制、短信权限授予限制、系统提供方延迟或强行停止会影响及时性；无法承诺后台永远实时运行。重新打开时补扫。真实机型、多段短信和后台可靠性仍待真机验收。

## 配置账期

信用卡页面点击「设置账单日」，选择每月 1–31 日并保存。未设置前不计算或猜测账期。当前是信用卡估算视图的统一账单日，不代表自动获知各卡银行账单规则。

- 账单日当天归结束的本期，次日起归下期。
- 短月将账单日夹到该月最后一天，例如 31 日在 2024 年 2 月为 29 日，在 2023 年 2 月为 28 日。
- 明确显示含首尾的起止日期，可查看上一/下一账期。按短信正文交易日期归期，不用接收日期替代、不猜未知年份，也不假装掌握银行实际入账日。
- 参考估算包含所选信用卡账户的全部币种，独立于下方列表的接收日期/原币筛选。演示账本的账单日配置与手机账本隔离。

## USD → CNY 估算口径

只计已识别信用卡消费；借记卡交易及信用卡还款本金不计消费。

1. 已确认的撤销/退款随原消费冲减，先得原币净额，再用**原消费的短信交易日**历史参考率折 USD；不在退款发生期再扣一次。未关联调整单列并标不完整。未来或缺日期的关联调整不擅自冲减，显示待核对。
2. USD 原币直接按 1；其它币种按该交易日期的有效参考报价折 USD。中间值全用 BigDecimal，不先按两位或三位截断/舍入。
3. 账期 USD 小计再乘最新可用 USD/CNY 参考率，界面最终显示两位小数。已确认净额为零时无需市场汇率即可得零，不等于将缺价当零。
4. 缺历史报价、未来交易日或不合格报价保留缺失；显示已换算/应换算笔数、日期异常、未归期交易和未关联调整。没有任何可换算数据时显示“暂缺”，不伪装完整零合计。只覆盖部分时明确标“已覆盖部分”。人民币报价缺失时 USD 已知部分仍可查看，CNY 显示暂缺。
5. 点击估算文字查看每笔原币净额、折 USD 结果、实际报价有效日、来源和获取时间。估算是短信已观察消费的参考，不是银行结算额、牌价、手续费后金额或官方应还账单。

## 公开汇率来源与日期

使用 [Frankfurter v2 官方文档](https://frankfurter.dev/) 描述的免费公共端点，无 API 密钥、凭据或订阅。来源提供历史、最新与供应商覆盖；识别一个 ISO 代码不保证行情源支持其所有历史日期。

默认接口可能给合成日期，不能直接当作交易日原始报价。因此：

- 先查询该币对的来源元数据，选取不晚于目标日、近 14 天内**最近实际来源有效日**；同日优先 ECB，否则按来源键确定性排序。
- 再读取该来源、该有效日的单独报价，并校验币对方向和有效日期。取原 JSON 数值字面量构造 BigDecimal，不把 Double 近似值当原报价。
- 明细记录来源键。供应商键不等于短信银行，也不代表中国银行牌价。报价沿用早于交易日的数据时明确显示实际有效日；没有可核验日期的合成/锚定报价不冒充当日市场报价。
- 正文交易日期在未来时不查询。报价晚于目标日、早于目标日前 14 天或方向不符时不采用。

仅做了 4 次有限云端公开可达性探测：TWD 覆盖元数据、合成历史日 TWD/USD、最新 USD/CNY、选定来源 TWD/USD 直接报价，均 HTTP 200；探测日期是合成公开日期，不含用户交易。发现历史接口的来源日期不尽相同，正因如此实现了上面的有效日选择。设备测试使用模拟公开响应，没有向行情源发送短信或实际手机资料。

[ECB 官方参考率说明](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)也明确参考报价按工作日更新并非交易执行价格；本应用只用于粗略估算。

## 缓存、失败与权限

- **新增 INTERNET 普通权限**。网络请求仅发送公开币种对与日期；不发送短信、卡尾、账户、商户、金额或用户标识。固定 HTTPS 汇率域名，不关闭证书验证；没有银行登录。
- 公开标量报价独立保存在本机 fx-cache.db，包含币对、请求日期键、来源有效日、BigDecimal 报价、来源、获取时间、到期/失败状态。短信账本表结构/版本不变，关闭系统备份。
- 历史报价缓存 30 天，最新报价缓存 1 小时；失败短期缓存 15 分钟。手动刷新不能在失败后一分钟内反复打请求。一次刷新最多 120 个 HTTP 请求，重复币种/日期用缓存；没有定时行情轮询。
- 网络失败可用已有合格缓存，并标缓存/过期状态及时间；本地没有就显示缺失。超出查询预算可稍后回到页面或用「更多 → 刷新公开参考汇率」继续。汇率任务与短信任务分开，失败或超时不阻塞账本。
- 演示模式不请求网络。真实设备网络可达性/证书和 Android 15 UI 没有在本次完成真机验收，失败按上述缺失/缓存规则处理。

## 安装与使用

1. 直接覆盖安装 0.1.3，不卸载/清数据。首次点击「授权自动扫描」并授予短信权限后自动读取；已授权且未主动暂停的旧用户回到 App 自动补扫。
2. 选择信用卡/借记卡。未识别内容默认隐藏，原文仍在工具菜单；必要时重新解析或核对来源。
3. 信用卡设置账单日，查看明确周期、USD 与 CNY 参考估算。缺失/缓存状态按界面提示核对，可点击看报价来源和有效日。
4. 只新增公开行情联网能力，短信和账户信息仍在本机。厂商后台、多段短信和还款双通知关联等既有验收限制保留。
