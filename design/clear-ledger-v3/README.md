# 精简记账设计 v3（设计提案，未发布到 Android）

基于 cf31853/0.1.5；本目录只包含可视原型、截图和离线规则规格，不修改App。自包含HTML可本地打开，窄屏顶部切换六页。全部合成数据，示例今天2026-06-25。字体沿用Noto Sans CJK，许可证见同目录。

## 首批实施

- 首页：借记总流入/流出/短信余额；信用卡独立。主屏无解释段落，口径、时间证据与汇率来源进入详情。无快照显示“—/无快照”；空范围显示“暂无流水”和切换范围入口，不能拿0替未知。
- 流水：点标签分类、勾选后批量分类、常用类别与自定义类别。分类是独立属性，不改原文/账户方向。批量操作有预览、撤销和审计。待分保留在金额和清单中。
- 商户：原始商户精确规则映射显示别名+默认类别；人工分类优先，批量套用旧记录需预览。借记短信无商户时不凭微信/支付宝或金额猜商户。类别停用保留历史，不静默删除。
- 图表：净消费构成环图、类别排行、每周趋势。默认账户/原币明确，信用卡独立。跨币种不能相加；选择参考折算时额外显示目标币、报价覆盖，缺率部分不当0。退款从原消费类别扣一次；转账/还款排除。采用原消费归属期重算净额，退款期显示调整记录；该口径固定在详情中，避免跨期双扣。
- 未关联调整不先扣消费，单列“待核对 N”；不能因金额未知隐藏整个记录。余额来自每账户最新有依据快照，与消费图表无关。
- 信用卡保留最近还款日对应账期、USD/CNY估算、报价覆盖和独立日期配置。短月取月底、冲突提示；提醒关闭。

## 关联规则替换差异

0.1.5要求唯一候选且30天内；新提案取消“多候选一律拒绝”，按用户规则允许重复同商户同金额，选择最早尚未有效冲销的一笔。默认不延续30天限制，以免无依据排除正常退货。

候选基本约束：同账本来源/SIM、同信用账户卡尾、同币种、消费日期不晚于调整；金额默认原消费金额=调整金额，且剩余可冲金额足够。自动关联还需两侧原始商户非空且精确相同，按完整交易日期时间升序，缺具体时间以日期+稳定来源ID排序。商户别名不能把不同原始商户合并为自动证据。日期/卡账户/币种缺失不自动配；无商户同金额仅人工。

已全冲销不候选；有部分冲销而余额不足不得再次配全额。部分退款不按同额自动规则匹配，人工点“其他金额/部分退款”进入剩余额度候选。已关联不重配，手工解除保留阻止自动重绑标记；重解析不覆盖人工。先收到调整后收到消费时，批量导入完成后重试未被人工锁定的调整。保留双方事件、原文、审计和解除操作。

关联页显示当前调整原文及候选消费原文（首条展开，可展开其余全文）；卡、币种、金额、商户、日期明确。截图中的退款正文无商户，所以仍需人工确认，展示的中文商户是手工补充，不冒充银行原文。未选项使用真正单选控件时，应确认后才写入。原型只演示选择/确认/解除状态，不写账本。
